04Qui exécute quoi, où

L'orchestrateur n'est pas un agent IA. Il ne raisonne pas : il applique un graphe déterministe, vérifie des hashes et bloque des gates. Le calcul lourd part sur un runtime jetable. Le Drive ne sert que de stockage durable.

GitHub Actions

ORCHESTRATEUR — déterministe
  • déclenche la phase autorisée
  • vérifie les gates et les hashes
  • écrit les checkpoints
  • reprend les unités inachevées
  • bloque tout si un gate échoue
Ne calcule pas. Ne décide pas. Ne dépasse jamais 6 h par job.

Kaggle / Colab

CALCUL JETABLE
  • exécute une partition ou un segment
  • écrit le résultat + son hash
  • meurt sans conséquence
  • piloté par token, sans navigateur
Rien d'irremplaçable ne vit ici. Tout est reprenable.

Google Drive

STOCKAGE DURABLE
  • certificats P1 et P2 (lecture seule)
  • 348 partitions certifiées
  • registres, splits, manifestes
  • checkpoints et reprises
Goulot réel : la latence Drive. Elle est mesurée, pas supposée.

Vous

  • 9 définitions scientifiques, une fois
  • 7 acceptations de phase

05Le cycle autonome, une fois lancé

  03:00 UTC  ORCHESTRATEUR réveille la phase autorisée
             │
             ├── vérifie KILL_SWITCH, budget, leases
             ├── recalcule le SHA-256 des 2 certificats
             ├── confirme 348 partitions + schéma inchangé
             │
  03:05      ├── découpe en unités (partition / segment d'hypothèses)
             │
  03:06      ├── dispatch vers le runtime jetable, N unités en parallèle
             │      chaque unité écrit : résultat + hash + checkpoint
             │      une unité perdue est replanifiée, jamais dupliquée
             │
  04:20      ├── agrège, vérifie la cohérence, écrit les rapports
             ├── évalue le gate de sortie de phase
             │
             ├── GATE PASS  → statut PHASE_COMPLETE_AWAITING_OWNER_REVIEW
             │                et ATTEND. Il n'enchaîne pas seul sur la phase suivante.
             └── GATE FAIL  → statut BLOCKED_WITH_RESUME
                              cause exacte écrite, aucune phase suivante

  À tout moment : une coupure ne coûte que l'unité en cours.
  Le lendemain, la même commande reprend exactement où elle s'était arrêtée.
C'est la réponse à « ça fonctionne sans moi » : le système avance seul à l'intérieur d'une phase autorisée, aussi loin que les gates le permettent. Il s'arrête de lui-même au gate, avec un dossier complet. Vous ne relancez jamais rien à la main — vous lisez et vous signez.

06Ce qui est automatisé, et ce qui ne le sera jamais

Automatisé (fiche §11)

  • exécutions de calcul
  • contrôles déterministes
  • checkpoints
  • reprises
  • logs
  • génération des rapports
  • blocage automatique des gates échoués
  • vérification des hashes
  • surveillance des ressources
C'est exactement la liste de la fiche. Rien de plus n'est revendiqué.

Jamais automatisé

  • inventer une formule pour remplir une famille
  • modifier silencieusement un paramètre scientifique
  • supprimer un résultat négatif
  • ouvrir le Holdout sans autorisation explicite
  • modifier un certificat hérité
  • inventer une valeur serveur
  • déployer en réel sans autorisation distincte
  • accepter une phase à la place du propriétaire
Ces huit interdictions sont écrites dans le code, pas dans une consigne. Elles lèvent une exception si on les contourne.

Conséquence architecturale majeure — la règle des 2 minutes. La stratégie est tick-informed : elle observe des ticks. Elle ne doit pas trader au tick. 13Le critère de réussite, tel que la fiche le définit

Le projet ne réussit pas parce qu'il produit beaucoup de fichiers, d'indicateurs ou une courbe séduisante. Il progresse quand : les données sont traçables, les variables causales, les hypothèses préenregistrées, les résultats négatifs conservés, les anomalies résistantes, les coûts honnêtes, les edges stables, les poids sans fuite, le portefeuille gelé survivant au Holdout et au miroir.

Si aucune stratégie ne franchit les critères, la conclusion correcte est NO_EDGE. C'est une conclusion scientifique utile, pas un échec informatique.
